문장 규칙의 정본은 `PROJECT_GUIDE.md` §6이다. 작업 전에 §6만 읽으면 된다(다른 절은 필요할 때만).

## 작업 절차

`2_스크립트/` 폴더에서 `py -X utf8`로 실행한다.

1. **메모리 조립본 확인** — `build_MMDD.py`는 보통 `fortune_memory.py draft MMDD`가 이미 만들어 두었다.
   72칸 대부분은 사용자가 pptx에서 확정한 문장을 재사용한 것이므로 **그대로 둔다**. 손댈 곳은 두 가지뿐이다:
   - `todo_MMDD.txt`에 적힌 칸(SUMMARIES에서 `("", "")`와 `# TODO 원문:` 주석이 붙은 칸) — 새로 작성.
   - `qa.py`가 FAIL로 지적한 줄 — 해당 줄만 수정.
   draft 없이 처음부터 써야 하는 경우에만 `src_MMDD.txt` 원문 전체를 읽는다.
2. **2줄 요약 작성** — 각 칸을 "1줄 = 상황, 2줄 = 조언"의 2줄로 압축한다. 원문 의미를 왜곡하지 않고,
   조사·주어를 살려 자연스러운 해요체로 쓴다. 줄폭은 상한 가까이 채워 원문 의미를 살리되 자연스러움을
   해치면서까지 채우지 않는다(목표 구간은 §6-2). 같은 파일의 기존 확정 문장들이 문체 기준이다.
3. **검증 루프** — `py -X utf8 qa.py MMDD`를 실행해 `RESULT: PASS`가 나올 때까지 지적된 줄만 고친다.
   어미 다양화 위반이면 이번에 새로 쓴 줄부터 어미를 바꾸고, 확정 문장은 마지막 수단으로만 바꾼다.
4. **완료 보고** — PASS 확인 후 "위반 0건, PASS"와 새로 쓰거나 고친 칸 목록을 보고한다. FAIL이 남은
   상태로 완료를 보고하지 않는다.

## 금지 사항

- 원문(`src_MMDD.txt`)에 없는 내용을 지어내지 않는다.
- `3_템플릿/` 디자인 템플릿을 수정하지 않는다.
- `qa.py`의 검증 로직을 우회하거나 완화하지 않는다. 규칙 자체가 잘못됐다고 판단되면 직접 고치지
  말고 사용자에게 보고한다(규칙 변경은 `PROJECT_GUIDE.md`와 `qa.py`를 동시 수정해야 하는 하드룰
  대상).
