**"운세 변환" 단계** — 3단계 파이프라인(운세 변환 → 운세 삽입 → 이미지 추출) 중 텍스트 작업만 담당한다.
정본은 `PROJECT_GUIDE.md`(워크플로우 §4의 2~4단계, 규칙 §6). `2_스크립트/`에서 `py -X utf8`로 실행한다.

## 인자 해석 ($ARGUMENTS)
공백으로 구분된 MMDD 코드 1개 이상(예: `0805`, `0805 0806`). 없으면 어느 날짜를 처리할지 되묻는다.

## 절차 (이 단계에서만 함)
각 MMDD 코드에 대해:
1. **원문 확보** — `2_스크립트/src_MMDD.txt`가 없으면, 해당 월 원본이 `1_원본엑셀/`에 있는지 확인 후
   `py -X utf8 extract.py "../1_원본엑셀/N월 운세.xlsx" MMDD` 실행.
2. **메모리 조립** — `py -X utf8 fortune_memory.py harvest`로 사용자가 pptx에서 고친 최신 확정 문장을
   메모리에 반영한 뒤, `py -X utf8 fortune_memory.py draft MMDD`로 `build_MMDD.py`를 만든다(표지 날짜·
   `SCORES`·메모리에 있는 칸의 SUMMARIES가 자동으로 채워진다). 이미 `build_MMDD.py`가 있으면 덮어쓰지 않는다.
3. **빈칸·FAIL 보완** — `todo_MMDD.txt`의 칸과 qa 지적 줄만 `fortune-writer` 서브에이전트가 채우거나
   고친다(PROJECT_GUIDE.md §6 규칙 전문 준수). TODO가 없고 qa가 PASS면 이 단계는 건너뛴다.
4. **검증** — `py -X utf8 qa.py MMDD` 실행, `RESULT: FAIL`이면 SUMMARIES를 고쳐 반복. `RESULT: PASS`까지.

## 범위 밖 (하지 않음 — 다른 명령의 몫)
- `py -X utf8 build_MMDD.py` 실행(pptx 생성/갱신) → `/운세삽입`
- `embed_export.ps1`(글꼴 임베드·PNG 내보내기) → `/이미지추출`

## 완료 보고
MMDD별 `qa.py PASS` 여부만 보고한다. `4_PPTX/MMDD.pptx`는 아직 새로 생성되지 않았음을 함께 알리고,
필요하면 `/운세삽입 MMDD`로 이어가라고 안내한다.
